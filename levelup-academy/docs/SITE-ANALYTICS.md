# Аналитика сайта levelup-academy.uz

Страница **Main Admin → Аналитика сайта** (`/site-analytics`). Сводит в один экран
то, за чем раньше ходили в три чужих кабинета.

## Что откуда берётся

| Вопрос | Источник | Есть? |
|---|---|---|
| По каким запросам находят в Google | Search Console API | да |
| Показы, клики, CTR, средняя позиция | Search Console API | да |
| Сколько человек пришло, сеансы, новые | GA4 Data API | да |
| **Среднее время на сайте** | GA4 `averageSessionDuration` | да |
| Откуда пришли (Google / прямые / соцсети) | GA4 `sessionDefaultChannelGroup` | да |
| Какие страницы смотрят и сколько времени | GA4 `pagePath` + `userEngagementDuration` | да |
| Страницы входа и доля отказов | GA4 `landingPage` + `bounceRate` | да |
| **На какой странице уходят с сайта** | своё событие `page_exit` | да, см. ниже |
| Страны, устройства | GA4 | да |
| Отправки формы заявки | GA4 событие `generate_lead` | да |

### Про точки выхода — важное

**Метрики exit rate в GA4 не существует.** Она была в Universal Analytics и при
переходе на GA4 её убрали; через Data API получить её нельзя никак.

Поэтому лендинг шлёт собственное событие `page_exit` — при `pagehide` и при
`visibilitychange → hidden`, один раз на страницу
(`frontend/landing-page/src/App.jsx`, компонент `ExitTracker`). Панель считает
это событие в разрезе `pagePath`.

Следствие: **данные копятся только с даты выкатки**, историю восстановить
невозможно. Дата зашита в `analytics.service.js` → `EXIT_TRACKING_SINCE` и
показывается на экране рядом с таблицей, чтобы короткий список не выглядел
поломкой.

Чтобы событие несло адрес нужной страницы, `trackPageView` дополнительно
делает `gtag('set', { page_path, page_location, page_title })`: в SPA gtag
запоминает адрес один раз, при `config`, и без этого все события уезжали бы на
первую открытую страницу.

### Чего здесь нет

- **Записи сессий и тепловые карты** — это Microsoft Clarity (проект
  `xvidms2zus`). У Clarity есть Data Export API, но он отдаёт только агрегаты и
  жёстко ограничен по числу запросов в сутки — встраивать смысла нет, проще
  открыть их кабинет.
- **Данные глубже 90 дней** — Search Console не хранит отчёты по запросам
  дольше 16 месяцев, а API по многим срезам ограничен ещё сильнее; периоды в
  панели ограничены 7 / 28 / 90 днями осознанно.

## Настройка (делается один раз)

Нужен **сервисный аккаунт Google**. Не OAuth-токен владельца: у приложения в
статусе Testing Google принудительно гасит refresh-token через 7 дней, и панель
молча переставала бы показывать данные раз в неделю.

1. **Создать сервисный аккаунт**
   [console.cloud.google.com](https://console.cloud.google.com/iam-admin/serviceaccounts)
   → проект `levelup-1c059` → IAM и администрирование → Сервисные аккаунты →
   Создать. Роль в проекте **не нужна** — доступ выдаётся не здесь, а в самих
   сервисах (шаги 3 и 4). Затем Ключи → Добавить ключ → **JSON**.

2. **Включить два API** в том же проекте:
   - Google Analytics Data API
   - Google Search Console API

   Без этого ключ рабочий, но запросы отвечают 403.

3. **Дать доступ в GA4**
   [analytics.google.com](https://analytics.google.com/) → Администратор →
   Управление доступом к ресурсу → добавить e-mail сервисного аккаунта
   (`...@levelup-1c059.iam.gserviceaccount.com`) с ролью **Читатель**.

   Там же, в «Настройках ресурса», взять **числовой идентификатор** — это и есть
   `GA4_PROPERTY_ID`. Это **не** `G-RWCK0B6TXP` из тега на сайте.

4. **Дать доступ в Search Console**
   [search.google.com/search-console](https://search.google.com/search-console) →
   ресурс `sc-domain:levelup-academy.uz` → Настройки → Пользователи и разрешения
   → Добавить пользователя, тот же e-mail, разрешение **«Ограниченный доступ»**.

   Проверено вживую 25.08.2026: ограниченного доступа хватает — Search Analytics
   API отдаёт запросы, показы, клики и позиции без единой ошибки. «Полный доступ»
   давать не нужно, он позволил бы менять настройки ресурса. Скоупы у сервера
   всё равно readonly.

5. **Положить в `backend/.env`** и перезапустить бэкенд:

   ```
   GOOGLE_SA_CLIENT_EMAIL=...@levelup-1c059.iam.gserviceaccount.com
   GOOGLE_SA_PRIVATE_KEY=-----BEGIN PRIVATE KEY-----\nMIIE...\n-----END PRIVATE KEY-----\n
   GA4_PROPERTY_ID=544460142
   GSC_SITE_URL=sc-domain:levelup-academy.uz
   ```

   `GOOGLE_SA_PRIVATE_KEY` — значение `private_key` из JSON целиком, переводы
   строк оставить литеральными `\n` в одну строку. Если хостинг режет такие
   значения (случается на Render) — положить тот же ключ в base64, код принимает
   оба вида.

Пока переменных нет, страница показывает эти же шаги списком, а не ошибку.

## Как устроено в коде

```
backend/src/modules/analytics/
  google.auth.js       JWT сервисного аккаунта + расшифровка ошибок Google
  ga4.client.js        GA4 Data API: два batchRunReports (10 отчётов)
  gsc.client.js        Search Console API: 6 параллельных запросов
  analytics.service.js сборка, тренды к прошлому периоду, кеш
```

Роут: `GET /api/main/site-analytics?days=7|28|90` (только `main_admin`,
`main.routes.js`). Фронт: `frontend/main-admin/src/pages/SiteAnalytics.jsx`.

Новых зависимостей нет: `google-auth-library` уже стояла ради проверки
id-token при входе через Google, и она же умеет JWT сервисного аккаунта.
Пакеты `googleapis` / `@google-analytics/data` не нужны — они тянут grpc и
protobuf ради двух эндпоинтов.

### Решения, которые легко случайно сломать

**Периоды у источников РАЗНЫЕ, и это не баг.** Search Console публикует данные с
задержкой 2–3 дня. Если брать окно по сегодняшний день, последние дни всегда
приходят нулями и график выглядит как обвал трафика. Поэтому окно GSC сдвинуто
на 3 дня назад (`gsc.client.js` → `LAG_DAYS`), а реальные даты подписаны на
экране рядом с цифрами.

**Итоги Search Console берутся отдельным запросом, а не суммой по дням.** Клики
и показы сложить можно, а средняя позиция — взвешенное среднее, сумма дала бы
бессмыслицу.

**Ошибка одного источника не убивает остальные.** `Promise.allSettled`: упавший
блок приходит `null` плюс текст ошибки в `errors`, остальные рисуются. Пустой
массив здесь означает ровно одно: Google ответил успешно и данных за период нет.
Проверено контрольным опытом с заведомо чужим ключом — сервис не падает и
отдаёт понятные тексты, а не нули.

**Кеш в памяти процесса, а не в Redis.** Upstash у нас уже упёрся в лимит
бесплатного плана. Смысл кеша не в квотах Google (они щедрые), а в скорости:
восемь сетевых вызовов — это секунды на каждое открытие страницы. TTL 10 минут,
ошибочные сборки не кешируются.

**Тренды считает бэкенд, не фронт.** Если предыдущего периода нет, дельта
приходит `null` — показать «+100%» вместо «сравнивать не с чем» это враньё в
цифре.
